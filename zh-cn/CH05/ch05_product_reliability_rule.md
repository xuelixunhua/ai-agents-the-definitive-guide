# Chapter 5：多 Agent 系统的乘积可靠性法则

## 这个 Notebook 在解决什么问题？

这个 Notebook 把多 Agent 系统背后的可靠性数学关系明确写出来，并实现两个简单模型。

第一个模型使用**乘积可靠性法则（Product Reliability Rule）**。在系统工程中，它通常以 [Lusser's law](https://en.wikipedia.org/wiki/Lusser%27s_law) 表述：当多个带有失败概率的组件按照串行方式组合，而且中间没有验证环节时，整个系统的成功率会随着组件数量增加而下降。

应用到多 Agent 流水线上：

$$
P(\text{系统成功})=\prod_{i=1}^{N}p_i
$$

这里的 $p_i$ 表示第 $i$ 个 Agent 正确完成自身任务的概率。

例如，如果每个 Agent 的准确率都是 98%，那么：

- 1 个 Agent：系统成功率为 98%；
- 5 个连续 Agent：成功率约为 $0.98^5=90.4\%$；
- 10 个连续 Agent：成功率约为 $0.98^{10}=81.7\%$。

所以，“每个 Agent 都挺准”并不意味着“多个 Agent 串起来以后仍然很准”。

## 第二个模型：在 Agent 边界增加验证

第二个模型在基准模型上加入了**验证（validation）**：每当一个 Agent 把结果交给下一个 Agent 时，先检查一次错误。

如果单个 Agent 的正确率为 $p$，验证机制能够捕获错误的比例为 $v$，那么经过验证后的有效正确率可以近似写成：

$$
p_{eff}=p+(1-p)v
$$

Notebook 中的示例使用：

```python
p = 0.98
v = 0.9
max_agents = 10
```

也就是：Agent 本身正确率 98%，而验证机制能够发现剩余错误中的 90%。

这时有效正确率为：

$$
0.98+(1-0.98)\times0.9=0.998
$$

10 个环节串联后的成功率从约 81.7% 提升到：

$$
0.998^{10}\approx98.0\%
$$

## 真正重要的结论

这个模型并不是为了精确描述所有现实中的 Agent 失败，而是为了建立一个非常重要的直觉：

> **多 Agent 系统天然会放大错误；真正提高可靠性的关键，往往不是继续提高模型能力，而是在任务边界建立验证和约束。**

因此，在真实系统中，比“增加一个更聪明的 Agent”更值得优先考虑的是：

1. 每一步有没有明确的输入输出契约；
2. 输出能否自动校验；
3. 错误是否会在传递给下游之前被发现；
4. 失败以后是重试、回退，还是交给人工；
5. 哪些步骤根本不需要 Agent，而应该使用确定性代码。
