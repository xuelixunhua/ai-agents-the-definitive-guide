# Chapter 5：Deep Agents 中文导读

对应原 Notebook：[`CH05/ch05_deep_agents.ipynb`](../../CH05/ch05_deep_agents.ipynb)

## 这个 Notebook 在解决什么问题？

这个 Notebook 展示的重点不是“如何再写一个会调用工具的 Agent”，而是如何把一个复杂任务拆成一套**可规划、可分工、可落盘、可复用**的 Agent 工作流。

示例围绕 LangChain 的 `deepagents` 项目展开，并直接运行其中的 content-builder-agent。这个 Agent 会先规划任务，再调用研究、写作、图片等能力，最后把结果写入明确的文件路径。

从工程角度看，它想回答的是：

> 当一个任务不再是“一次模型调用”，而是包含研究、规划、执行、检查和产物管理时，Agent 系统应该怎样组织？

## Notebook 展示的核心流程

从代码可以看到，Notebook 先安装 `deepagents`、LangChain、LangGraph、Tavily 等依赖，然后克隆 Deep Agents 仓库，进入 `content-builder-agent` 示例目录并直接运行内容生成任务。

示例任务要求 Agent：

1. 研究 2026 年 AI Agent 在招聘中的应用；
2. 起草 LinkedIn 内容；
3. 生成社交媒体图片；
4. 创建最终的 LinkedIn 帖子文件。

运行时 Agent 会先输出计划，并要求按照约定的相对路径保存产物，例如：

```text
linkedin/<slug>/post.md
blogs/<slug>/post.md
research/<topic>.md
```

这说明 Deep Agent 的重点之一，是让 Agent 不只“回答”，而是**围绕长期任务维护一套文件化工作空间**。

## Deep Agent 和普通 Agent 的区别

普通 Agent 常见结构是：

```text
用户问题
  ↓
模型思考
  ↓
调用一个或几个工具
  ↓
返回答案
```

Deep Agent 更接近：

```text
目标
  ↓
规划任务
  ↓
拆分子任务
  ↓
调用子 Agent / 工具
  ↓
读取和写入文件
  ↓
检查阶段性产物
  ↓
继续执行
  ↓
形成最终交付物
```

因此，它更适合长任务、研究任务、内容生产、代码任务等需要多个步骤和中间状态的场景。

## 最值得理解的 4 个工程概念

### 1. 规划（Planning）不是最终答案

Agent 先给出计划，并不等于任务已经完成。规划的作用是把一个模糊目标变成可执行步骤。

真正可靠的系统要区分：

- 计划是什么；
- 哪一步正在执行；
- 哪一步已经完成；
- 哪一步失败；
- 最终产物在哪里。

### 2. 文件系统可以充当长期工作记忆

复杂 Agent 不应该把所有上下文都塞进 Prompt。

把研究结果、草稿、图片和中间产物写入文件，可以：

- 降低上下文长度；
- 让不同 Agent 共享结果；
- 让任务可恢复；
- 让人类可以直接检查中间产物；
- 形成天然的审计记录。

这也是为什么 Notebook 里对相对路径规则做了严格约束。

### 3. 子 Agent 的价值是“职责分离”，不是数量越多越好

把研究、写作、图片生成拆成不同角色，是为了让每个模块有清晰职责。

如果一个任务本身并不复杂，继续增加 Agent 只会引入：

- 更多延迟；
- 更多成本；
- 更多状态同步问题；
- 更高的错误传播概率。

因此，Multi-Agent 的判断标准不是“能不能拆”，而是“拆开后是否真的降低复杂度”。

### 4. 路径、文件格式和产物规范，本质上也是 Contract

Notebook 中对输出路径的明确要求看似只是文件管理，实际上是 Agent 工程中的一种契约：

> Agent 不仅要完成任务，还要按照下游系统能够理解的格式交付。

这和 API schema、Pydantic model、数据库字段约束本质相同。

## 对实际项目的启发

如果把这个模式迁移到研究型项目，可以形成这样的结构：

```text
研究目标
  ↓
Planner Agent
  ↓
├─ 数据检查
├─ 基准模型实验
├─ 特征实验
├─ 误差诊断
└─ 结果总结
  ↓
统一写入 experiments/ 与 reports/
```

例如一个预测研究 Agent，可以把每次实验的：

- 参数；
- 数据版本；
- 指标；
- 图表；
- 结论；
- 下一步假设

全部写入标准目录，而不是只在聊天窗口里留下自然语言结果。

## 一句话总结

Deep Agent 的核心不是“更聪明的模型”，而是：

> **把复杂任务变成有计划、有状态、有文件、有分工、可恢复的长期工作流程。**
